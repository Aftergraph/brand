# STEWARD Character Law

Status: locked product-extension law.

## Identity

STEWARD is one Aftergraph node entity expressed through roles and states. Roles are a view. Evidence is the truth.

## Invariants

- Preserve the same core silhouette across roles.
- Preserve the dark visor, copper eyes, halo ring with nodes, angular torso, slim limbs, and Bounded Node custody ring.
- Role differences are limited to accent, emissive state, and functional accessory.
- State changes must be legible through pose, signal, or a documented semantic symbol.
- The character must remain sophisticated and system-like. No plush, toy, chibi, mascot-costume, or decorative robot treatment.
- The Bounded Node geometry is canonical. Do not close the custody-ring gap or move the copper node.
- Character animation is a projection of system state. It does not become a source of authority, execution truth, or verification truth.

## Canonical role vocabulary

STEWARD role visuals follow `persona-roles.json` and the actor-persona role vocabulary:

Reviewer, Subscriber, Maintainer, Observer, Auditor, Integrator.

Every role is the same STEWARD entity. Role differences are restricted to accent, emissive state, functional accessory and pose. Role selection does not create authority or verification truth.

## Canonical state vocabulary

Idle, Thinking, Planning, Executing, Inspecting, Waiting, Blocked, Approval, Verifying, Approving, Succeeded, Failed.

## Accessibility

Every animated state requires reduced-motion parity with the same final semantic state and a textual label when the state matters to a user decision.
