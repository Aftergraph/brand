# STEWARD Deck Template

Use this structure for product, partner, research, and internal review decks. Remove sections that are not supported by evidence.

## 01 - Cover
STEWARD by Aftergraph. One sentence describing the exact audience problem. Use the Bounded Node with clear space.

## 02 - Human intent
State the user goal and the failure mode of ungoverned automation.

## 03 - System law
"Capability may accelerate only as fast as evidence, alignment, authority and verification can keep up."

## 04 - Mission graph
Show Goal -> Mission -> Work -> Attempt -> Action -> Evidence -> Verification. Mark canonical owners.

## 05 - Authority boundary
Show AIE and Trust Gateway explicitly. Do not depict STEWARD as granting its own authority.

## 06 - Execution
Show Runtime and WORKS. Separate requested work from durable execution truth.

## 07 - Evidence
Show receipts, exact subject identity, and independent verification. Never use fake telemetry.

## 08 - Presence
Use the keeper, state system, or live WebGL view to explain projection and human steering. Label it as projection.

## 09 - Proof
Only include measured or independently verified results. Add exact dates, versions, populations, repositories, and commit SHAs where relevant.

## 10 - Next decision
State the decision, unresolved risks, dependencies, acceptance criteria, and next executable step.

- Accent: Steward Copper #C2703D.

- Settled success: Moss #3E7C59 only when evidence supports success.
- Display: Sora.
- Interface and labels: Manrope.

## Motion

Deck motion is optional. If used, prefer simple state transitions under 420 ms. No decorative particles, camera shake, AI glow, or fake system activity.
